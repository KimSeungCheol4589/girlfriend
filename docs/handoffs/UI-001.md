## 1. 구현 범위

DESIGN.md 3·4·9를 기준으로 홈·추억·꾸미기 화면과 공통 UI를 만들었다.
**로그인·서버 저장·사진/커버 업로드·상대방 공유는 구현하지 않았다. 앱은 화면 확인용 데모 모드다.**

### 화면

| URL | 구현 내용 |
| --- | --- |
| `/` | 커버(테마별 합성 그라데이션 또는 로컬 커버 미리보기), 공간 이름·한 줄 소개, 함께한 날짜 배지, 고정 추억·최근 추억·가고 싶은 맛집 섹션. 섹션 순서·표시 여부는 꾸미기 설정을 따른다 |
| `/memories` | 월·태그 필터(URL 검색 매개변수), 최신순 목록, 사진 카드·사진 없는 기록 카드 |
| `/memories/[id]` | 사진 갤러리(썸네일 전환), 본문, 날짜·장소·태그, 수정·홈 고정·삭제(확인 대화상자) |
| `/memories/new`, `/memories/[id]/edit` | 제목·본문·날짜·장소·태그·사진 미리보기 폼 |
| `/customize` | 테마 3종, 포인트 색상, **커버 이미지 고르기**, 섹션 순서·표시, 미리보기, 취소 시 원복, 미저장 경고 |
| `/restaurants`, `/settings` | ‘준비 중’ 안내 화면. 만들 항목과 담당 작업 ID를 명시 |

### 상태 화면

- 로딩: `app/loading.tsx`, `app/memories/loading.tsx`, `app/memories/[id]/loading.tsx` 스켈레톤
- 빈 화면: 기록 없음 / 필터 결과 없음 / 고정 추억 없음 / 홈 섹션 전부 숨김 / 커버 미선택

- 찾을 수 없음: `app/not-found.tsx`, 없는 추억 ID 전용 화면(수정 화면 포함)

### 디자인

- 콘텐츠 최대 폭 1,120px, 모바일 좌우 16px / PC 24px 여백 (DESIGN.md 4.1)
- 모바일 하단 고정 메뉴(홈·추억·맛집·꾸미기) + 768px 이상 상단 메뉴, 설정은 헤더에 별도 배치
- 주요 터치 영역 44px 이상(`spacing.touch`), 전역 `:focus-visible` 외곽선, 본문으로 건너뛰기 링크
- 테마 키 `cream` / `rose` / `sage`, 색상 변수 `background`·`surface`·`text`·`muted`·`accent`·`border`
- 포인트 색상 위 글자색은 WCAG 상대 휘도로 자동 선택하고, 대비 4.5:1 미만이면 화면에서 알린다
- 본문은 `whitespace-pre-wrap` 텍스트로만 렌더링한다. 임의 HTML을 해석하지 않는다 (DESIGN.md 5.3)

## 2. 커버 이미지 미리보기 (이번 보완)

꾸미기 화면에 커버 이미지 고르기를 추가했다. 데모 범위 안에서만 동작한다.

| 항목 | 구현 |
| --- | --- |
| 형식·용량 | 추억 사진과 같은 규칙(JPEG·PNG·WebP, 파일당 10MiB). 공통 검사 함수 `src/lib/images.ts`를 양쪽이 함께 쓴다 |
| HEIC | 추억 사진과 같은 안내로 거부 |
| 미리보기 | 브라우저 `URL.createObjectURL`로만 만든다. 어디에도 올리지 않는다 |
| objectURL 정리 | 거부된 파일은 즉시 해제. 다시 고르기·빼기·취소·화면 이탈 시 적용되지 않은 주소를 해제. 적용 후 교체되면 이전 주소를 저장소가 해제 |
| 취소 | ‘취소하고 되돌리기’ 확인 후 마지막 적용 상태(커버 포함)로 복귀 |
| 미저장 경고 | 테마·색상·섹션과 함께 커버 변경도 미저장 상태로 계산. `beforeunload`와 확인 대화상자 |
| 적용 | 홈 커버에 반영. 사진 위에 밝은 막을 덮어 글자 대비를 유지 |
| 문구 | 커버 아래에 “이 브라우저에서만 보입니다. 업로드하지 않았고 상대방에게 전달되지 않아요.” 표시 |

### 저장 계약과의 분리

DESIGN.md 4.2의 `coverAssetId`와 데모 미리보기 주소를 **섞지 않는다.**

- `DemoCustomization`에 `coverAssetId: string \| null`을 두고 데모에서는 **항상 null**이다.
- `customizationSchema`는 `coverAssetId`를 UUID 또는 null로만 받는다. `blob:` 주소는 검증에서 거부된다.
- 로컬 커버 미리보기는 계약 바깥의 `DemoState.coverPreview`(`DemoCoverPreview`)에 따로 둔다.
- `applyCustomization(customization, coverPreview)`로 두 값을 분리해 넘긴다.
- 위 성질은 단위 테스트로 고정했다(`tests/unit/cover.test.ts`).

실제 커버 업로드는 `prepareUpload` / `finalizeUpload` / `saveCustomization`(DESIGN.md 7) 구현 후에 붙인다.

## 3. 오류 표시 정리 (이번 보완)

일반 사용 흐름에서 내부 오류 코드를 노출하지 않도록 바꿨다.

| 위치 | 이전 | 현재 |
| --- | --- | --- |
| 추억 폼 검증 실패 | `VALIDATION_ERROR` 표시 | 사람이 읽는 요약과 필드별 메시지만 |
| 추억 저장·삭제·고정 실패 | `NOT_FOUND` 등 코드 표시 | 안내 문장만 |
| 꾸미기 검증 실패 | `VALIDATION_ERROR` 표시 | 안내 문장만 |
| 추억·화면 찾을 수 없음 | `NOT_FOUND` 모노스페이스 표시 | 아이콘과 안내 문장만 |
| 렌더 오류 경계 | `digest` 또는 `RETRYABLE_ERROR` | `digest`가 있을 때만 ‘문의 번호’로 표시. 사용자가 실제로 전달할 수 있는 값이라 남김 |

`ErrorNotice`의 `code` prop은 남겨 두되, 사용자가 쓸 수 있는 값에만 넘긴다는 규칙을 주석으로 적었다.
DESIGN.md 7의 오류 코드 정의 자체는 `src/lib/contracts.ts`에 그대로 있다.

| 구분 | 위치 | 내용 |
| --- | --- | --- |
| 계약 상수 | `src/lib/contracts.ts` | DESIGN.md의 길이·장수·용량 제한, 테마·섹션 키, 오류 코드. 데모 데이터 없음 |

- 화면 상단에 항상 보이는 **데모 모드 배너**로 로그인·업로드·공유 저장이 없다는 사실을 밝힌다.

- 커버·맛집·설정 영역에도 각각 “아직 만들지 않았다”는 문구를 남겼다.
- 사진은 `public/artwork/*.svg` 합성 일러스트와 브라우저 `objectURL` 미리보기만 쓴다. 원격 미디어 의존이 없고 실제 인물 사진·개인 정보를 넣지 않았다.

## 5. 입력 제한 반영 (DESIGN.md 5.2 / 8.2 / 9)

| 항목 | 값 |
| --- | --- |
| 제목 | 1~80자 |
| 본문 | 10,000자 이하 |
| 장소 | 100자 이하, 선택 |
| 태그 | 최대 5개, 각 20자. `#` 제거·중복 제거·대소문자 무시 |
| 사진 | 0~10장, 파일당 10MiB |
| 커버 | 1장, 10MiB |
| 이미지 형식 | JPEG·PNG·WebP 허용, HEIC는 전용 안내로 거부 |
| 날짜 | `YYYY-MM-DD` 실제 존재하는 달력 날짜 |
| 함께한 날짜 | 한국 달력 기준, 시작 당일 1일, 미래 시작일 거부, 미설정 시 배지 숨김 |
| 홈 섹션 | 3개 키가 정확히 한 번씩, 순서·표시만 변경 |
| 포인트 색상 | `#RRGGBB`만 허용 |
| 커버 asset ID | UUID 또는 null. 데모에서는 항상 null |

오류 표시는 상단 요약 + 필드별 메시지이며 첫 오류 필드로 포커스를 옮긴다.
삭제 확인에는 대상 제목과 함께 지워지는 사진 장수를 표시한다.

### 새로 추가한 커버 테스트

단위(`tests/unit/cover.test.ts`, 17건):
형식·용량 경계(10MiB 정확히/초과), HEIC·GIF 거부 메시지, PNG·WebP 허용,
`blob:`이 아닌 주소 거부, `isLocalPreviewUrl` 판별, 취소 확인용 `isSameCover` 비교,
그리고 **계약 분리**: 기본 `coverAssetId`가 null임, 커버를 골라도 꾸미기 계약이 바뀌지 않음,
`coverAssetId`에 `blob:` 주소를 넣으면 검증 실패, UUID만 허용,
검증 통과 객체에 미리보기 관련 키가 남지 않음.

브라우저(`tests/e2e/app.spec.ts`, 4건 추가):
커버 선택 → 미저장 표시 → 적용 → 화면 내 이동 후 홈 커버 반영 → **새로고침하면 기본 커버로 복귀**(저장하지 않음을 확인),
지원하지 않는 형식 선택 시 이유 표시와 미저장 상태가 생기지 않음,
커버 선택 후 취소하면 원래 상태 복귀, 꾸미기 화면 가로 넘침 없음(`scrollWidth - clientWidth <= 0`).

마지막 항목은 앞선 CUA 확인에서 통과했던 ‘꾸미기 가로 넘침 없음’을 커버 UI 추가 후에도 유지하려고 회귀 테스트로 고정한 것이다.

## 8. 미실행 검증 (통과로 취급하지 않음)

- **실기기 모바일 확인.** 에뮬레이션 뷰포트만 사용했다.
- **Firefox·WebKit.** Chromium만 실행했다.
- **접근성 자동 검사(axe 등)와 스크린 리더 확인.** 도구를 도입하지 않았다.
- **Dev Container 안에서의 실행.** ENV-APP-001의 차단 항목이다.
- **보안·권한 검증.** 서버·DB·인증이 없어 검증 대상이 없다. 현재 앱은 누구나 열 수 있는 데모 화면이다.
- **실제 사진·커버 업로드, EXIF 제거, 재인코딩(DESIGN.md 8.2).** 구현하지 않았다.
- **동시 수정 충돌·`version`·`requestId` 처리(DESIGN.md 8.4).** 서버 작업이 없어 구현하지 않았다.

## 9. 설계 문서에 대한 메모

- DESIGN.md 3의 “20개씩 더 보기” 페이지네이션은 구현하지 않았다. 데모 데이터가 5건이라 목록을 한 번에 보여 준다. `MEMORY_PAGE_SIZE` 상수만 `contracts.ts`에 남겼다. 실제 데이터 연동(MEM-001) 시 커서 기반으로 구현해야 한다.
- DESIGN.md에는 추억 날짜(`memory_date`)의 미래 날짜 제한이 없어 검증에 넣지 않았다. 관계 시작일과 맛집 방문일만 미래를 거부한다.
- 홈 고정 추억은 한 번에 하나만 유지하도록 구현했다. DESIGN.md에 개수 제한이 명시돼 있지 않으므로 확인이 필요하다.
- 미저장 이동 확인의 실제 범위(이전 판의 설명이 과도해 바로잡는다):

  - **브라우저가 확인함**: 탭 닫기·새로고침(`beforeunload`, 문구는 브라우저가 정한다).
