## 주요 동작

- 필터는 URL에 유지한다. 목록은 `created_at DESC,id DESC` 커서로 20개씩 조회하며 마이크로초 정밀도와 중복 제거를 유지한다. 뒤로 가기에서 검색 입력도 URL과 일치하도록 hydration/pageshow 때 동기화한다.
- 한국 달력 기준 미래 방문일을 거부한다. wishlist의 방문일은 null이며 후기는 visited에서만 저장한다.
- 삭제·방문 취소는 제거될 후기를 보여주고 확인한다. 확인 후 상대 후기가 추가/수정/삭제되면 버전 충돌로 거부하고 최신 내용을 다시 확인한다.
- 정보 편집은 충돌 시 작성 입력을 유지하며 사용자가 최신 버전을 불러오기 전에는 덮어쓰지 않는다.
- 불확실한 실패에서 같은 입력은 같은 requestId로 재시도한다. 동기 ref로 처리 중 재제출을 막고, 성공 후 화면 이동하는 작업은 이동 완료 전까지 잠금을 유지한다.
- hydration 전 입력/제출을 비활성화해 이벤트 유실·네이티브 GET 제출·마운트 시 방문일 덮어쓰기를 방지한다.
- 지도 URL은 HTTPS와 허용 호스트만, 외부 내용을 가져오지 않는다. 사용자 문자열은 텍스트로 렌더링하고 DB 오류 원문은 노출하지 않는다. 실패를 빈 목록이나 저장 성공으로 표시하지 않는다.

## DB 계약 변경과 적용 상태

두 migration은 2026-09-21 기존 로컬 테스트 DB에 적용 완료했다. 재개 시 재적용/reset하지 않았다. 운영 DB 적용은 하지 않았다.

1. `delete_restaurant_confirmed(uuid,boolean,integer,uuid)` 추가: 맛집 행 잠금·버전·후기 삭제 확인을 검사한다. 기존 `delete_restaurant(uuid,integer,uuid)`의 public/anon/authenticated 실행 권한은 회수했다. 앱은 대체 함수만 사용한다.
2. `save_review`/`delete_review`: 맛집→후기 순서로 잠그고, 후기 변경과 같은 트랜잭션에서 맛집 version을 증가시킨다. 반환에 `restaurantVersion`을 추가한다. 같은 요청 재생은 버전을 다시 올리지 않는다. 정보 수정도 상대 후기 변경 후에는 충돌하는 보수적 계약이다.

테이블 직접 쓰기는 기존대로 금지다. MEM RPC는 변경하지 않았다. 총괄은 통합 시 `docs/database/CONTRACTS.md` 4절에 위 함수·권한·버전 계약을 반영해야 한다(공유 문서라 담당이 수정하지 않음).

## 제한과 후속

- 실제 모바일 기기·운영 배포·운영 데이터 검증은 미실행. 데모 E2E 재실행은 하지 않았으며 기존 맛집 데모 분기는 유지했다.
- 지도 허용 호스트는 DB 설정과 앱 상수 양쪽에 있어 변경 시 함께 관리해야 한다.
- 이름 검색의 `*`는 PostgREST 치환 때문에 한 글자 와일드카드로 처리해 결과가 약간 넓어질 수 있다. 지역/종류는 정확 일치, 제안 목록은 최대500행에서 수집한다.

- 저장 성공 후 화면 이동 자체가 실패하면 폼 잠금을 유지한다. 새로고침으로 복구해야 하며 중복 등록 방지를 우선했다.
- 홈 맛집 요약은 담당 범위 밖이며 실제 연결은 총괄 후속 작업이다. 독립 검토·총괄 검증 전 dev 반영 금지, main 직접 변경 없음.
