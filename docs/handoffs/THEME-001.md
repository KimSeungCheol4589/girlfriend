## 변경

실제 모드의 꾸미기 화면에서 테마·포인트 색상·커버·홈 섹션 순서와 표시 여부를 미리 보고 공유 저장한다. 저장 전 미리보기는 현재 문서 테마나 DB를 변경하지 않으며 취소는 저장된 설정으로 돌아간다. 충돌 시 초안을 남기고 명시적으로 최신 설정을 다시 읽는다. 중복 제출과 응답 유실 재시도에는 동일 요청 ID를 사용한다.

추억 고정은 기존 추억 저장 계약을 사용하여 항목별 별도 저장한다. 꾸미기 저장과 원자적으로 묶인다고 표시하지 않으며 이미 저장한 고정은 꾸미기 취소로 되돌리지 않는다.

커버는 추억 사진의 정규화·검증·정리 파이프라인을 재사용한다. 공통 확정 함수에 필수 `memory | cover` 목적 인자를 추가했고 기존 추억 호출은 명시적으로 memory를 전달한다. 사용자 세션으로 공간·업로더·목적·상태·경로를 확인한 뒤에만 관리자 작업을 수행한다. 커버 조회는 인증된 전용 경로와 private/no-store 응답을 사용한다.

빠르게 커버를 교체할 때 이전 파이프라인이 새 파일을 지우지 않도록 각 파이프라인의 파일을 정리한다. 미저장 취소·앱 메뉴 이동에서는 대기 파일만 버리고 저장된 커버와 저장 결과가 미확정인 파일을 보존한다.

기존 데모 48건의 최초 실행은 45 PASS / 3 timeout이었다. 동일 테스트 단일 worker 재실행으로 2건 PASS, 나머지 모바일 사진 순서 테스트는 로딩 중 기본 시간 상한을 초과했다. 제품·테스트 원본 변경 없이 제외된 진단 설정(전체 120초, assertion 20초)에서 해당 1건이 22.1초로 PASS했다. 최초 기본 설정 전체 실행을 통과로 취급하지 않으며 개발 서버 지연에 대한 잔여 검증 한계로 인계한다.

초기 THEME 검증의 중복 버튼 선택자, Next 경로 안내 alert 포함, SQLSTATE 기대값, 이미 선택된 테마 클릭 문제를 수정했다. 현재 값을 읽고 다른 테마를 선택하며 비활성→활성→저장 후 version+1을 검증한다. 본인 추억 목적 파일의 커버 지정은 기존 DB 계약상 GF422이며 외부 업로더는 GF404다. HTTP GET 차단은 실제 404로 별도 확인했다.

## 잔여 한계·후속

- 탭 강제 종료·새로고침의 대기 업로드 정리는 최선 노력이다. 남은 파일은 기존 24시간 만료 정리 절차 대상이며 자동 실행기는 이번 범위가 아니다.
- 앱 내부 링크와 탭 닫기 경고는 있으나 브라우저 뒤로/앞으로 이동의 미저장 확인에는 기존 App Router 제약이 남는다.
- 홈 커버에는 실패 대체 UI가 있으나 편집기 커버 미리보기에는 없다.
- 실제 휴대폰·운영 배포·운영 자격 증명 검증은 미실행. 모든 자동 검증은 로컬 합성 데이터로 수행했다.
- 테스트 전용 THEME 합성 공간 정리는 독립 검토 후 진행 예정. 재사용한 MEM·인증 계정은 재설정·삭제하지 않는다.
- 독립 검토와 잔여 회귀 결과를 확정한 뒤 총괄에게 로컬 SHA를 인계한다. 총괄만 dev 통합을 결정하며 main 승격·배포는 별도다.
