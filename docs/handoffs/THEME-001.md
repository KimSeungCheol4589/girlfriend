## 변경

실제 모드의 꾸미기 화면에서 테마·포인트 색상·커버·홈 섹션 순서와 표시 여부를 미리 보고 공유 저장한다. 저장 전 미리보기는 현재 문서 테마나 DB를 변경하지 않으며 취소는 저장된 설정으로 돌아간다. 충돌 시 초안을 남기고 명시적으로 최신 설정을 다시 읽는다. 중복 제출과 응답 유실 재시도에는 동일 요청 ID를 사용한다.

추억 고정은 기존 추억 저장 계약을 사용하여 항목별 별도 저장한다. 꾸미기 저장과 원자적으로 묶인다고 표시하지 않으며 이미 저장한 고정은 꾸미기 취소로 되돌리지 않는다.

커버는 추억 사진의 정규화·검증·정리 파이프라인을 재사용한다. 공통 확정 함수에 필수 `memory | cover` 목적 인자를 추가했고 기존 추억 호출은 명시적으로 memory를 전달한다. 사용자 세션으로 공간·업로더·목적·상태·경로를 확인한 뒤에만 관리자 작업을 수행한다. 커버 조회는 인증된 전용 경로와 private/no-store 응답을 사용한다.

빠르게 커버를 교체할 때 이전 파이프라인이 새 파일을 지우지 않도록 각 파이프라인의 파일을 정리한다. 미저장 취소·앱 메뉴 이동에서는 대기 파일만 버리고 저장된 커버와 저장 결과가 미확정인 파일을 보존한다.

## 독립 검토(`f27fbd9`) 후속 수정

읽기 전용 독립 검토가 P2 2건·P3 5건을 지적했다. 아래는 그 뒤 **구현 세션이 바꾼 동작**이다.
위 검증 표는 이 수정 **이전** 결과이므로, 관련 항목은 다시 실행해야 한다.

| 지적 | 바뀐 동작 |
| --- | --- |
| P2-1 | 홈의 맛집 섹션이 추억 요약과 무관하게 그려진다. 추억 두 섹션을 모두 숨겨도, 추억 조회가 실패해도 표시 상태인 섹션은 남고 실패 안내는 추억 섹션 자리에만 들어간다. |
| P2-2 | 대기 커버를 되돌릴 때 화면에 알린다(`onDiscarded`). 초안이 그 파일을 가리키고 있으면 저장된 커버로 되돌려, 교체하려던 새 사진이 실패해도 초안은 늘 저장 가능한 값이다. 폐기된 asset을 저장에 보내지 않는다. 정리는 그대로 파이프라인 단위다. |
| P3-1 | "최신 설정 불러오기"가 올리던 커버 초안도 함께 정리한다. 두 미리보기가 서로 다른 사진을 보여 주지 않는다. 저장 시작 시 불러오기 대기 표시를 내려 잘못된 안내가 뜨지 않게 했다. |
| P3-2 | 색상 형식이 잘못되면 저장을 막고, 상단 요약을 띄우고, 입력란으로 포커스를 옮긴다. 오류 문단을 `aria-describedby`로 입력과 연결했다. |
| P3-3 | 서버 반영 여부를 모르는 응답(재시도 가능·원인 불명)에서는 정리 허용 플래그를 내리지 않는다. 확정 응답일 때만 내린다. |
| P3-4 | 순서 이동으로 버튼이 비활성화되면 같은 항목의 반대 방향 버튼으로 포커스를 옮기고, 바뀐 자리를 `role="status"`로 알린다. |
| P3-5 | 업로드 실패 문단에 `role="alert"`를 붙였다. 준비 단계 검증 실패는 사유에 맞는 문구를 쓴다(용량 초과를 형식 오류로 안내하지 않는다). 커버 용도·미준비 거부에 대한 구체 문장을 추가했다. |
| P3-6 | 보류. 총괄 판단 사항이라 리팩터링하지 않았다. |

추가한 브라우저 회귀(순수 함수 흉내가 아니라 실제 상태 전이):

- 추억 두 섹션을 숨겨도 맛집 섹션이 홈에 남는다(“전부 숨김” 안내가 뜨지 않는 것까지 확인).
- 확정된 커버를 **실패하는 파일**로 교체해도 초안이 저장 가능한 값으로 돌아온다(되돌리기 선택지가 사라지고 저장 버튼이 비활성, 이전 파일은 `deleting`, 저장된 커버·버전 불변).
- 충돌 뒤 "최신 설정 불러오기"가 대기 커버까지 정리한다.
- 잘못된 색상 입력이 저장을 막고 오류가 입력과 연결되며 포커스가 이동한다(고친 뒤 저장되는 것까지).
- 순서 이동 후 포커스 이동과 상태 안내.
