## 변경 동작

실제 로그인 공간에서 추억 작성·조회·수정·삭제·홈 고정을 제공한다. 목록은 날짜와 ID 내림차순으로 20개씩 조회하며 월·태그 조건을 URL에 보존한다. 홈에는 고정 추억 최대 3개와 최근 추억 3개를 표시한다. 기존 데모는 명시적 데모 모드에서 유지한다.

Server Action은 사용자·공간을 다시 확인하고 일반 작업에는 사용자 세션과 기존 DB RPC/RLS를 사용한다. 같은 입력의 응답 유실 재시도는 같은 requestId로 재생한다. 고정 변경도 화면에서 읽었던 스냅샷과 원래 버전을 보내므로 상대의 수정을 덮어쓰지 않는다. 충돌·검증·네트워크 실패 시 입력을 보존한다.

사진은 브라우저에서 방향 반영·긴 변 2,048px 제한·재인코딩·EXIF 제거 후 DB가 발급한 고유 경로에 `upsert:false`로 올린다. 서버는 사용자 RLS로 업로더·공간·목적·경로를 확인한 다음 실제 파일의 크기·형식·치수·메타데이터·전체 디코딩을 검증한다. 서버 확정기는 파일을 덮어쓰지 않는다. 불변 파일에서 나온 실제 값과 결정적인 확정 요청 ID로 기존 service 전용 RPC를 호출한다.

사진 읽기는 사용자 세션과 Storage 정책을 모두 거치며 응답은 `private, no-store`다. 서버 전용 키 `MEM_SUPABASE_SERVICE_ROLE_KEY`는 `server-only` 클라이언트에서만 읽고 사진 확정·정리에만 사용한다. 설정이 없으면 새 사진 올리기만 비활성화되며 글 저장·기존 사진 조회는 유지된다.

삭제·첨부 해제·업로드 취소 뒤에는 DB가 반환한 경로 중 같은 공간의 `deleting` 자산만 재확인해 삭제한다. 정리 실패는 기록 저장을 되돌리지 않고 보류로 안내한다. 앱 내 메뉴·뒤로가기로 폼을 떠날 때 미첨부 업로드를 정리하며, 저장된 자산은 제외하고 DB에서도 첨부 자산 취소를 차단한다.

실제 E2E는 공유 편집·재로그인 지속성·월/태그/페이지·동일404·직접 RLS/Storage 차단·중복/응답 유실·고정 재시도/충돌·삭제/로그아웃을 확인했다. 사진은 미첨부 권한, EXIF/형식/40MP/손상 거부, 불변 업로드, 저장 후 공유, 메뉴/뒤로가기 정리, 모바일 두 장 재정렬과 상대의 첨부 제거까지 확인했다. 통합 검증은 동시 확정·RPC 중단·ready/첨부 후 재호출·확정/취소 경쟁에서 객체 해시가 유지됨을 확인했다.

검증 중 발견한 sharp 타입 import, 404 본문 영역, 위변조 테스트의 multipart 파일 부분 교체, 폼 이탈 정리를 Claude가 수정했고 관련 검증이 통과했다. 픽스처의 커버 해제 UPDATE는 버전 증가 규칙을 반영하도록 수정한 뒤 실제 정리·재생성으로 검증했다. 9/22 최초 사진 off 실행은 테스트 진입 전 서버 시작 timeout으로 종료됐고, 직접 시작 진단 후 동일 설정 재실행이 통과했다. 제품 코드를 바꿔 이를 우회하지 않았다.

## 미실행·제한·후속 작업

- 독립 검토는 승인됐으며 차단 지적은 없다. 총괄은 최신 dev와의 통합 차이·관련 검증을 별도로 확인해야 한다.
- 실제 휴대폰·개인 사진·HEIC 변환·접근성 자동 검사는 미실행이다. 모바일 검증은 Chromium 375×812 뷰포트다.
- 탭 닫기·새로고침·로그아웃 중 정리 통신은 보장하지 않는다. 미첨부 사진은 24시간 만료 대상이며 자동 정리 실행기는 없다.
- 파일 삭제 뒤 자산 메타데이터 제거는 운영자 수동 절차다. `expire_stale_assets`는 공간 한정이 아닌 전역 함수임을 문서화했다. 공유 테스트 DB에서 전역 만료 정리는 실행하지 않았다.
- ICC 색 프로필은 허용한다. 404 화면 내용은 같지만 스트리밍으로 HTTP 상태가 200일 수 있다.
- 필터 선택지는 최근 1,000개에서 수집한다. 홈 섹션 순서·표시 저장은 THEME-001 범위다.
- 배포·운영 데이터 변경·dev/main 직접 반영은 수행하지 않았다.
