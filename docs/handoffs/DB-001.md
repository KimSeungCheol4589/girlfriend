# DB-001 최종 인수인계

- 담당 브랜치: `feat/db-foundation` · 통합 대상: `dev`
- 상태: **제품 SQL 구현·로컬 DB 검증·새 Claude 세션 독립 검토 완료**
- 통합 준비: **DB-001은 dev 통합 검토 준비 완료**. 총괄의 범위 검토·관련 검증 후 반영한다.
- 최종 제품 검토 대상: `59fa491ed2efb85c1281fa4d1dbcf3f6142db696`.

## 변경 요약과 범위

DESIGN의 11개 제품 테이블, 제약·인덱스·RLS·최소 SQL 권한, 비재귀 권한 확인 함수, 공간 생성·2인 초대·만료/재사용 방지, 수정 버전과 중복 요청, 자산 수명주기, 추억·맛집·개인 후기·꾸미기·프로필 RPC를 구현했다. `space-assets` 비공개 버킷은 정확한 생성 경로와 업로더·공간·첨부 상태로 객체 접근을 제한한다. 업로드 완료는 일반 사용자에게 허용되지 않으며 신뢰된 서버 역할만 호출한다.

변경 파일은 다음 범위뿐이다.

- `supabase/migrations/`: 16개 SQL. 초기 11개와 실제 검증/독립 검토에 따른 전진 수정 5개. 전체 목록과 적용 순서는 [DB README](../database/README.md)에 있다.
- `supabase/tests/`: 단일 세션 스위트 7개와 공통 도우미, 실행 안내, 5개 경쟁 시나리오의 2세션 러너·픽스처·검증·정리 SQL.
- `docs/database/README.md`, `CONTRACTS.md`, `SECURITY.md`: 적용·부트스트랩·RPC 서명·오류·권한·후속 작업 계약.
- 이 보고서 `docs/handoffs/DB-001.md`.

앱/src/package/lockfile/인증 UI/TASKS/공통 설계는 수정하지 않았다. 기능 브랜치에 최신 승인 dev 변경을 보존 병합했으며 dev/main에 직접 반영하지 않았다.

## Claude 구현·독립 검토 이력

- 승인된 `require_escalated` 네트워크 실행에서 도구 없는 연결 확인 1회 성공: CONNECTION_OK.
- Claude Code 2.1.273의 신규 구현 세션에서 작성하고, 정확한 동일 세션 ID로 3차례 수정했다. 제품 코드를 Codex가 대신 작성하지 않았다.
- 각 독립 검토는 별도의 새 세션에서 실행했고 Edit/Write를 제공하지 않았다. 구현 세션의 자기 평가는 독립 검토로 계산하지 않았다.
- 1차 검토: base `dc1f04205fe840546283c74a4ed15ab84d337e1f` → `517c9a5c31b2824746967f27d1ef177ad19df43a`. 정규식·새 첨부 소유권·충돌 매핑·보조 함수 범위·테스트 신뢰성 지적.
- 2차 검토: 전체 구현과 수정 커밋 `7d5d143f01bbcb5d5d9cb1ffb9d2f1f684e18e57`. 기존 보안·무결성 지적 해결 확인. 낮은 등급 D8~D11(응답 필드·정규식 보호 검사·잠금 동기화·상태 문서)을 추가 수정했다.
- 마지막 검토: delta `7d5d143f01bbcb5d5d9cb1ffb9d2f1f684e18e57` → `59fa491ed2efb85c1281fa4d1dbcf3f6142db696`. 정확성·보안 차단 지적 없음. D8~D10 해결 확인. 낮은 등급 문서 지적 2건(expiresAt null 허용, path 진단 키)은 최종 문서 커밋에서 반영했다.
- 최종 문서 커밋은 위 검토 대상의 제품 SQL·테스트를 변경하지 않는다. 검토 JSON is_error=false, 실행 종료 코드 0 확인.
- 프롬프트·JSON 결과·세션 ID·실행 로그는 Git 제외 `.agent-runtime/DB-001-*`, `apply-*`, `retest3-*`, `race-v4.log`에 기록했다. 비밀 키/실제 이메일은 보고서에 넣지 않았다.
- 권한 우회 옵션·전역 설정 변경 없음. 일부 보조 셸 검색/정적 점검 요청은 Claude 허용 목록에서 거부됐으며 Read/Grep 또는 Codex 검증으로 대체했다. 제품 파일 쓰기·필수 테스트 실행은 차단되지 않았다.

처음 적용 후 실제 테스트에서 URL 정규식 SQLSTATE2201B와 커밋 시 지연 트리거 권한 오류를 발견했고 후속 migration으로 수정했다. Git Bash 경로 변환 문제도 러너에서 해결했다. 모든 최종 수치는 이 수정 후 재실행 결과이며 첫 실패를 성공으로 계산하지 않았다.

## 미실행 검증·잔여 작업

- 실제 이미지 바이너리 디코딩·EXIF 제거·객체 존재/내용 검증 워커는 **미구현**. SQL은 업로드 완료 호출 주체와 메타데이터 제약만 강제한다. MEM-001의 신뢰된 서버 워커 구현 전에는 실제 사진 기능의 완료로 취급하지 않는다.
- 실제 Storage HTTP 파일 업로드/다운로드와 서명 URL, 앱 로그인·초대 UI/E2E, PostgREST 새 서명 연결은 미검증이다. SQL 메타데이터 권한 테스트와 구분한다. 표준 업로드를 대상으로 하며 TUS/S3 multipart는 미검증이다.
- service_role JWT에 sub가 있는 별도 배포 구성, 계정 정지/삭제 세션 처리, 파일 정리·고아 객체 대조·중복 요청 보존 정책은 후속 설정/검증 대상이다.
- 운영 migration 적용·백업/복원·배포는 실행하지 않았다. 공간 탈퇴·교체·전체 삭제는 설계상 MVP 범위 밖이다.
- 설계 차이(모든 변경 requestId, 새 첨부 소유권, trusted finalize 서명, SQLSTATE 매핑 등)는 [계약](../database/CONTRACTS.md)과 [보안 문서](../database/SECURITY.md)에 기록했다.

AUTH-001은 DB 계약을 연결하고, MEM-001은 신뢰된 업로드 검증 워커를 구현해야 한다. 다음 작업은 총괄 배정 후 시작하며 담당자가 임의로 시작하지 않는다.
